## Architecture invariants

1. **ORM only, async.** SQLAlchemy 2.0 `Mapped[...]`, `AsyncSession` via `Depends(get_db)`.
   Never raw SQL for CRUD. This is **not** the WebStaffr 3.0 raw-SQL codebase; do not carry
   patterns across.
2. **Tenant scoping is defense in depth.** Every query filters `organization_id`. The
   repository layer is the last line, not the router. The worst bug found last session was
   publish tasks looking up rows by primary key with no org filter.
3. **State machine authority.** `post.status` changes only via `ApprovalStateMachine`. This
   is now enforced structurally: a `ContextVar` + `@validates` guard on the `Post` model
   raises on any assignment to a persisted or detached row.
4. **Immutable history.** Content edits create a new `PostVersion`; a `before_update`
   listener raises if you try to mutate one.
5. **Audit everything.** Every transition writes an `AuditLog` row in the same transaction.
6. **No in-memory workflow state.** Recovery is deterministic from `execution_nodes`.
7. **Enum labels in the database are UPPERCASE member names** (`'PENDING'`, not
   `'pending'`). Nothing passes `values_callable`. An assertion against a lowercase literal
   silently matches nothing. Note `docs/sql/smm_gtm_bridge.sql` has this wrong in places —
   treat that file as design intent, never copy its literals.

## Migration traps (all three have bitten already)

1. **A new model is invisible until imported in `app/models/__init__.py`.** Do that
   *before* autogenerating, or you get an empty migration and a false sense of safety.
2. **Autogenerate omits `import app.core.db_types`** while emitting
   `app.core.db_types.GUID()`. Add it by hand or the migration raises `NameError`.
3. **Autogenerate proposes dropping `ix_execution_nodes_org_open` and
   `ix_execution_nodes_org_workflow_ref` every single time.** They are intentional
   hand-written composites from `412a32e37eb2` that aren't declared on the ORM model.
   **Delete that block from any generated migration.** Decided 2026-07-24 to accept this
   over adding an `include_object` filter to `alembic/env.py`.

Also: adding a `NOT NULL` column needs a `server_default` or it fails on populated tables,
and name your foreign keys — autogenerate emits `drop_constraint(None, ...)` in
`downgrade()`, which cannot execute.

Always verify: `upgrade head` → `downgrade -1` → `upgrade head`.

## What works end to end today

WS3.3 sends campaign intent → lands as Campaign + Posts + PostVersion v1 + PENDING
Approvals + an execution graph + audit row, in one transaction that rolls back completely
on failure → approval gates it → publishing is tenant-scoped, idempotent, and retries with
backoff → analytics roll up weekly.
